# ДЗ НОМЕР ДВА

## Описание проекта

Проект представляет собой систему для работы с файлами, состоящую из двух микросервисов:
Для запуска docker compose up -d --build. Тестов нет

**!!!ВАЖНО!!!** В СВАГГЕРЕ НАЛО ВЫБРАТЬ СЕРВЕР filestoring ИЛИ fileanalyser, ИНАЧЕ РАБОТАТЬ НЕ БУДЕТ

1. **File Storing Service** - сервис хранения файлов
   - URL: `http://localhost/filestoring/swagger-ui/index.html`
   - Функционал:
     - Хранение файлов
     - Генерация хешей
     - Выдача контента файлов

2. **File Analyser Service** - сервис анализа файлов
   - URL: `http://localhost/fileanalyser/swagger-ui/index.html`
   - Функционал:
     - Подсчет слов в тексте
     - Подсчет букв
     - Анализ параграфов
## Детали реализации

### Общая структура сервисов

Каждый сервис реализован по принципам MVC архитектуры с использованием Spring Framework:

- **Модель (Model)**:
  - Сущности БД реализованы по стандартам Spring Data
  - Используются JPA-аннотации для маппинга

- **Контроллер (Controller)**:
  - Реализованы через `@RestController`
  - Содержат endpoint'ы API
  - Используют стандартные HTTP-методы (GET, POST, PUT, DELETE)

- **Репозиторий (Repository)**:
  - Интерфейсы, расширяющие `JpaRepository`
  - Реализуют доступ к данным
  - Поддерживают основные CRUD-операции

- **Билдер (Builder)**:
  - Паттерн Builder для создания сложных объектов
  - Позволяет гибко конструировать модели

- **Сервис (Service)**:
  - Содержит основную бизнес-логику
  - Реализует взаимодействие между компонентами
  - Обеспечивает транзакционность операций

### Хранение данных
- В качеству томов в корневой папке должны быть созданы папки oploads и cloudword, в которых будут храниться загруженные файлы.
